# Governance

Conversation Success Coach uses maintainer-led governance.

- Maintainers review changes for correctness, security, accessibility,
  responsible-use boundaries, and compatibility with the documented scope.
- Material changes to analysis, safety policy, data handling, identity,
  integrations, or delivery capability require tests and an explicit discussion
  of failure modes.
- Automatic sending, impersonation, hidden profiling, and high-impact
  decision-making are product-boundary changes, not routine features.
- Decisions are recorded in pull requests and issues whenever disclosure is
  safe.
- Maintainer and ownership changes are reflected in `CODEOWNERS`.

The project may evolve this model as the contributor community grows.
